Docker Compose for Apple’s container.

Apple’s container runs Linux containers natively on your Mac, but it has no Compose. This plugin adds a compose command: your existing compose.yaml files, unchanged, running on the real Docker Engine inside one lightweight Linux machine.

$ brew install RobertDeRose/tap/container-compose-plugin

Other ways to install View the source

Free and open source under Apache-2.0. macOS 15 or newer on Apple silicon.

dbpostgres:17
cacheredis:7
apibuild: ./api
webnginx:1.27

Everything Compose does, on the runtime Apple ships.

The plugin doesn’t reimplement or translate Compose. It runs the real docker compose in a Linux machine managed by container, and handles the parts that make it feel local.

Your Compose files work as they are

Every subcommand, flag, profile, and file format works, because it is Docker Compose. No conversion step, no unsupported keys.

compose up -d
compose logs -f api
compose exec db psql

Published ports on localhost

TCP ports your services publish appear on 127.0.0.1 and ::1 within seconds, the way Docker Desktop does it. Loopback only, never your LAN.

ports:
  - "8080:80"   # open localhost:8080

A Docker socket for your other tools

Point the docker CLI, your IDE, or Testcontainers at the Docker Engine inside the machine. Fast enough to run in every new shell, and it doesn’t boot the machine until a tool connects.

export DOCKER_HOST="$(compose --socket-path)"
One machine for every project
All projects share a machine named compose. Images, volumes, networks, and build cache survive compose down and restarts.
Your home folder at the same path
Your macOS home directory is mounted read-write at the same path inside the machine, so bind mounts like ./src:/app just work.
Shuts itself off when idle
Set an idle timeout and the machine powers off after Docker goes quiet. The next command boots it again.
Feels native to container
Compose help reads as container compose, and bash, zsh, and fish completions are generated without booting anything.
Never touches your data on its own
The plugin records which machine it created and refuses to adopt one it didn’t. Installing, upgrading, or removing it never deletes the machine.
Nothing installed behind your back
No daemon is registered and no Apple service is replaced or patched. It’s a plugin directory with one executable in it.

How a command runs

A thin client over the public APIs of container. Your first command creates the machine; every later one reuses it.

  1. compose makes sure the plugin is registered with your current container, then hands off to container compose.
  2. container finds the plugin and passes it your arguments.
  3. The plugin checks your working directory is under your home folder and picks the environment to forward.
  4. It starts the background forwarder for ports and the Docker socket, if one isn’t running.
  5. It creates the compose machine on first use, or verifies the existing one is its own.
  6. It boots the machine if needed and waits for Docker.
  7. It runs docker compose inside the machine, relaying input, output, terminal size, and signals.

Docker Desktop and Podman Desktop are full desktop apps that bring their own virtual machine. If you already use Apple’s container, or want the least software running on your Mac, this plugin adds Compose and nothing else.

Choose container compose if

  • You already run Apple’s container and miss Compose.
  • You want Compose without a desktop app or a license to track.
  • Your projects need exact Docker Compose behavior, not a reimplementation.
  • You live in the terminal and don’t need a dashboard.

Choose something else if

  • You need a GUI to browse containers, images, and logs.
  • Your team works across Windows, Linux, and Intel Macs.
  • Your services publish UDP ports to the host.

Install

Pick the route that matches how you installed container. Homebrew and mise also give you the compose command, which re-registers the plugin whenever container is upgraded, so it keeps working.

Homebrew

Installs container too if it’s missing, and adds a shorter compose command that keeps the plugin registered across brew upgrade.

brew install RobertDeRose/tap/container-compose-plugin
container system start
compose --help

mise

Installs container and the plugin with no elevated privileges, and adds the compose command. It registers the plugin with mise’s container on first use, and again after mise upgrade.

mise use -g container 'github:RobertDeRose/container-compose-plugin[bin_path=cli,strip_components=1]'
container system start
compose --help

Apple’s installer

Apple’s package installs under /usr/local, so the installer asks for your password. Download with gh or curl, not a browser: release builds aren’t notarized.

gh release download --repo RobertDeRose/container-compose-plugin --pattern '*-darwin-arm64.tar.gz*'
shasum -a 256 -c container-compose-plugin-*-darwin-arm64.tar.gz.sha256
tar -xzf container-compose-plugin-*-darwin-arm64.tar.gz
container system start
./compose/install.sh

This route doesn’t add the compose command. Type container compose wherever this page says compose, and run the installer again after upgrading container.

From source

Needs Swift 6.2 or newer.

git clone https://github.com/RobertDeRose/container-compose-plugin.git
cd container-compose-plugin
container system start
make install

This route doesn’t add the compose command. Type container compose wherever this page says compose, and run make install REPLACE=1 again after upgrading container.

Then, from any project in your home folder

cd ~/projects/my-app
compose up -d

The first run pulls the machine image and boots the machine, so it takes longer. After that, commands start in the already-running machine.

Good to know before you start
  • Projects and bind mounts must be under your home folder.
  • All projects share one machine, so give projects distinct names if they would collide.
  • UDP ports aren’t forwarded to localhost.
  • A port another Mac app already uses isn’t forwarded, so localhost reaches that app instead. AirPlay Receiver holds 5000 and 7000; pick other ports or turn it off.
  • Forwarding finds published ports through Docker’s userland proxy, which is on by default. If you disable it, reach services through the machine’s address instead.
  • Your host Docker credentials and SSH agent aren’t reused inside the machine.
  • Deleting the machine with container machine delete removes all Docker data, including volumes.
